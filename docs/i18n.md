# Internationalisation (i18n)

Le portfolio fonctionne en bilingue **français (`fr`) / anglais (`en`)**, avec `fr` comme langue par défaut.

## 1. Détection et routage

- Source unique de vérité : `app/lib/langues.ts` exporte `LOCALES = ["fr", "en"]` et `LOCALE_PAR_DEFAUT = "fr"`.
- `proxy.ts` inspecte les en-têtes `Accept-Language` du visiteur via `negotiator` et `@formatjs/intl-localematcher`.
- Toute requête sans préfixe linguistique (ex. `/`) est redirigée en `307` vers `/{locale}`.
- Les routes techniques (`/api`, `/admin`, `/medias`, assets Next.js, fichiers avec extension) sont exclues du proxy.
- Si une langue inconnue est demandée dans l'URL (ex. `/de`), la page renvoie un code HTTP `404` immédiat grâce à `dynamicParams = false` et `estLocale()`.

## 2. Textes statiques de l'interface

- Stockés dans `app/dictionnaires/fr.json` et `app/dictionnaires/en.json`.
- Chargés côté serveur par `app/recup-dictionnaire.ts` via `getDictionary(locale)`.
- Typage strict : le type `Dictionary` est dérivé de `fr.json` et le dictionnaire anglais est garanti d'avoir exactement les mêmes clés au moment de la compilation TypeScript.
- Contient uniquement les textes statiques : titres des sections, boutons génériques (« Détails », « Présent »), métadonnées de base.

## 3. Données dynamiques en base de données

- Les projets et les expériences sont stockés dans Neon avec un modèle de traduction relationnel :
  - `projet_traduction` (`projet_id`, `lang`, `nom`, `description`)
  - `experience_traduction` (`experience_id`, `lang`, `nom`, `lieu`, `description`)
- **Règle de repli automatique (fallback)** :
  - Le français (`fr`) est obligatoire lors de la création d'un contenu.
  - Si un visiteur consulte le site en anglais et qu'un projet ou une expérience n'a pas encore de traduction anglaise, la requête SQL applique automatiquement un `COALESCE(trad_en.nom, trad_fr.nom)` pour afficher la version française plutôt qu'un texte vide.

## 4. Formatage localisé des dates

- `app/lib/dates.ts` fournit la fonction `formaterDate(iso, lang)`.
- Utilise `Intl.DateTimeFormat(lang, { month: "short", year: "numeric", timeZone: "UTC" })`.
- Le fuseau horaire forcé en UTC garantit que le rendu côté serveur (SSG) et l'hydratation côté client produisent exactement la même chaîne de caractères, éliminant tout risque d'erreur d'hydratation.
